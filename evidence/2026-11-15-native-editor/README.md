# A native app in a real VS Code editor tab

[Play the checked 18-second clip](native-editor-checked.mp4). It shows one public Wayland entry dialog moving from the shell pane into a registered VS Code editor Pane, receiving `tabnative`, parking while a text tab is active, reopening, returning to the pane when its tab closes, and disappearing after native submission.

`receipt.json` retains the exact target, viewer instance, output, scene, geometry, app ID, PID and toplevel ID. The original `<app>` DOM element is checked throughout. Native stdout independently confirms the keyboard input; the text model remains unchanged. `finalization.json` identifies the finalized MP4 hash and media checks. All scenario observations fall within the 18-second excerpt, beginning approximately at 00:50:09.140 UTC on 15 November 2026. No invented frames or UI replacements are used. The clip is a functional demonstration, not a latency benchmark.

Earlier CDP new-document injection did not enter the shell's actual JS realm; that failed probe is retained privately.

Limits: one native editor, one editor group, a fixed-size dialog and an explicit US-layout input subset. Arbitrary applications, multiple native editor groups, child popups, IME, physical keyboard latency and login-desktop operation remain unqualified. No Domicile engine change was needed for this feature.
